1Status: other problems, loading and errors

The same rows in other situations. A problem always reads the same way: the row moves under Needs attention with the warning icon, the words and the red edge, and says what to do. When a part cannot be read, the row says so in words instead of guessing, and the headline counts it as something to look at. If nothing at all can be read the page says it cannot tell, and says what to check from outside, because SignalHub cannot report its own outage. Sample data only.

The page says Needs attention when the database check is down; no push service is set up; every device that has a push address failed its last push (with at least one such device), which means the push service is likely down; the events waiting to be pushed are above 20 and have not fallen over two checks in a row (the server returns one number, so the page remembers the last one while it is open); pushes were given up since the page opened (the page keeps the count it saw when it opened, not a count since the server started); or a part could not be read. A single device's failure is not the headline: it is a row warning (“2 devices' last push failed”) with a link to Devices filtered to Push problems. These thresholds are the page's, and are one line each in the technical notes. C above is the fourth rule, A is the first, B the second, D the sixth.

Which push service is failing is not known by the server (it keeps only the last push result per device), so a failing service is worked out from the devices, as in ST2. A push counter per service would make this exact (a server item, listed below).

2The rail's status button on every other section

The button at the foot of the rail is a small copy of the Status headline, so the operator sees a problem on whichever section they are in. What it reads and how often is the one rule written in the shell page's note (Admin - Shell and Producers, shell A); it is not repeated here. Pressing it opens Status. Each state differs by its icon and its word as well as its colour.
