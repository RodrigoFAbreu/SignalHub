1Answering an event on the web page: the event pane with the answer card

The app's option A (the owner's pick), laid out like 7a of Web - Inbox and producers: navigation rail, the list, and the open event beside it. The question is an answer card under the message, headed Your answer: select, then Send answer. Choosing is not sending, so the button is the confirmation and there is no extra dialog (DESIGN.md 4.1: an answer goes to a producer and cannot be taken back). A choice may have a description (at most 200 characters), shown under its label in the secondary text color and not at all when empty. The same event in every frame unless it says otherwise: Merge R82 into main? from ci-pipeline, a single choice, Merge (“Squash-merge now; CI passed.”) or Hold (no description), with an optional note. Signed in as Rodrigo (Admin), the producer's owner. The wording is the app's, word for word; what differs on the web is said in each note. The card is at most 560 px wide, so it never stretches across a wide pane. The web page does not notify, so a question reaches a browser only as a row in the inbox: the card is the only place to answer. The page re-reads an open event when its tab regains focus, and after any 409, so a card that went stale turns into the current state by itself. When a question is answered, closed or deleted, the notification on every phone it reached is removed, never replaced (the app's pages show that); the web page only has to show the result.

2The inbox list: the To answer line, the To answer chip and its empty state

The web inbox has no chips row today (its filters sit behind the Filter icon). Questions add one, as the app's inbox has (the chips are added by R81 and are the only chips of the inbox): Unread and To answer above the list, 48 px hit areas (the chip is 32 px, with margin). Unread is the same switch as the unread-only option of the Filter dialog, which keeps producer, category and severity. A row of a question adds one line under the usual meta line, in words, so the state is never only an icon or a color: To answer in primary (with the closing time when there is one) for a question this person may answer now; You answered · Merge, Ana answered · Hold or Closed · nobody answered in grey once decided. A question this person may not answer shows Waiting for Rodrigo in grey (the names from whoCanAnswer, owner first: Waiting for Rodrigo or Ana, Waiting for Rodrigo, Ana or Rui), so the row never looks finished. An open question stays in To answer whatever its read state. Mark all as read marks it read like any event; it stays in To answer until it is answered or closed. The unread dot is read state only. Rows use the short form Closed · nobody answered; the card uses the full Closed · nobody answered in time.

4Who can answer: the setting on your producer's page

The app's 4a to 4d on the web page. A Who can answer section in the pane of your own producer (7b), between the people it is shared with and Keys, in the app's order. You are always the first row and can't be removed. Adding opens a dialog like the app's picker (checkbox rows, names only), listing only people who can see the producer: on a Private producer the people it is shared with, on a Public one everyone on the server. The owner never learns who has subscribed, so the dialog says they need to be. Removing is confirmed because it changes what someone else can do (DESIGN.md 4.1). The section is shown to the owner only. Accessible names: Remove Ana (the close button of a row), Add people who can answer. Changes take effect at once; a person removed from Who can see it, or revoked, leaves the list in the same moment (the server does it) and answers they already gave stay.
