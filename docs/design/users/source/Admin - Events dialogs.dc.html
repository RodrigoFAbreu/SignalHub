5Dialogs: send a test event and delete events by rule

Companion to Admin - Events.dc.html (options and detail). Both are dialogs, not forms under the list. 760 px stages stand for the dialog over the 1440 frame. Dialog actions are text buttons, 48 px high: the confirming action in the primary colour, a destructive confirming action in the error colour (never a filled red button). Every dialog is labelled by its title (aria-labelledby), starts its focus on the first field (or on Cancel when it only asks to confirm), and returns the focus to the control that opened it.

After Send the dialog closes, the list refreshes and the snack bar links to the new event (it opens in the pane). The snack bar sits at the bottom left of the list area, above the pager row, so the pager (Newer, Older) and the pane's foot stay reachable. It carries no Undo (a sent event is not taken back; Delete is in the pane); Retry is only shown on a failure. It leaves after 6 seconds, stays while it has the pointer or the focus, and is announced with role=status. The table is a grid: the header cells are plain labels, because the API has no sort (events come newest first); the filter chips are in the order of the task: Read state, Severity, Push problems (marked with a dashed note on the Events page), then Producer, Category, User and Received.

Count events asks the server for a dry run (nothing is deleted) and the dialog answers in words with the number. Only now does the destructive action appear, as an error-coloured text button that carries the count (no filled red button, as in every dialog). Editing the rule goes back to the counting step, so a count never confirms a different rule. The deletion is all-or-nothing on the server; success is a snack bar “Deleted 42 events” with no Undo.
