1Devices: the list and the detail

Shell A (rail, table, fixed 480 px pane), one version. Every device and every signed-in browser is one row: the name with its tags (Admin device on a device only, Browser, Revoked), its user, when it was last active, and how its push is going in plain words. Search and filters (All, Active, Revoked, Push problems, Kind, User) are done in the page from the one list the management API returns. The pane answers “is this device fine, and what can I do to it”; codes and ids live only in its Technical details fold. Connect a device is a tonal header button. Connect a device, Rename, Revoke and Delete are in-page dialogs (see Admin - Devices dialogs).

Columns: Device (name and tags), User, Last active, Push. Last active is to within a minute (the server records it once a minute). Push says one of: Working (the last push was accepted), Last push failed, retrying (a temporary failure with tries left, at most 5 in all), Gave up after 5 tries (the fifth try failed too), Push address rejected (the push service refused it for good and it was removed), No push address (browsers, and devices that have not registered one) and Revoked. A browser has no push address by design, so it reads as neutral grey, not as a problem. “Push problems” counts only rows that need a look (red text), not browsers. Status links here: its Devices row opens this list with Push problems already chosen. There is no sort control: the page orders the list itself, active devices first by last activity, revoked ones last. The page refreshes every 30 s while visible and after each change. The rail's status button follows the one rule written in the shell page's note.

Accessible names. Landmarks: the rail is a navigation named “Sections”, the list and pane are the main region. Headings: the section title “Devices” is the level 1 heading; the open pane's title is level 2. Each repeated action names its object: “Rename Rodrigo - Pixel 9”, “Revoke Rodrigo - Pixel 9”, “Delete Rodrigo - Old Pixel 6”. Icon buttons have names: “Refresh the device list”, “Close the detail”. A row is one button named by its device, user and push words.

The failure code is said in words first; the raw code and ids are in the fold. TRANSIENT_FAILURE: “The push service did not accept it this time.” while tries remain, and “Gave up after 5 tries.” once the fifth has failed. INVALID_TARGET: its address was refused for good and removed. PERMANENT_FAILURE: “The push service refused it.” (the code is in Technical details). UNSUPPORTED_PROVIDER: “This device's push service is not supported by this server.” Event titles come from the event the id points to; if it was deleted the line says “That event was deleted”.

Needs a server change (S7): a final marker on delivery records. Until then the page can tell that a push gave up only by its count of tries, so “Gave up after 5 tries” is drawn from that count.
