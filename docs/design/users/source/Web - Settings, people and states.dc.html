People mirrors the app's People tab (list by role with the role's one-line explanation, a person with Basic or Mod, devices and producers). The route uses the person's id, not the name. Admin is drawn but not available: it is set on the admin page. Invite is the app's 3d: first the form (name, Basic or Mod, an optional first device name), then the pairing QR on screen, which the invitee's phone scans from the admin's browser: that works, since the QR is not for this browser. The link is the real form (signalhub://pair?server=…&code=shpc1_…, shortened here); there is no typed code. Non-admins never see this section: the rail entry is hidden and the address #people shows the not-found state in 8h.

What the API gives: the list comes from GET /api/v1/client/users, which has only role, activeDevices and hasPaired for each person. So a row's second line is only “N devices”, “Invited · not paired yet” when they have never paired, or “No devices” when they paired before and have none active now. A person's page asks for their producers separately, with GET /api/v1/client/users/{id}/producers (id, name, visibility, disabled), and shows each one's name with Public or Private and “Disabled” when it is. There is no joined date: the API does not give one.
