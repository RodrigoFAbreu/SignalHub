1The admin page in the light theme

The key admin screens in the light set of the users' design system (primary #515b92, secondary container #e0e1f9, surface #fbf8ff, surface container low #f5f2fa). The design is dark first; these frames show that nothing in the admin drawings depends on the dark values. The drawings switch with a light class on the frame, exactly as the web page's own light frames do (9d); the build switches the same tokens with prefers-color-scheme, as admin.css and app.css already do. The stylesheet admin-events.css holds both token sets, and every colour that used to be written out (the error row tint, disabled and busy buttons, scrims, shadows, the browser frame) is a token now, so the dark frames did not change. Sample data only.

2Contrast of the light set, from the token values

Computed with the WCAG 2.1 relative luminance formula from the light token values in admin-events.css. Text needs 4.5:1 (large text 3:1); the parts of controls that carry meaning (borders, icons, the focus ring) need 3:1. Every pair passes. The lowest text pair is primary on surface container highest (4.98); the lowest part is the outline on surface container highest or on an error container (3.48). One dark-first rule was wrong in light and is fixed: a revoked row dimmed its text with the outline colour (4.06 on the list, under 4.5), so in light the revoked row's text is on-surface-variant (8.4) and the Revoked tag carries the state, as in dark. Disabled controls are exempt (about 2.3 : 1, as in dark). Dark values were checked in the R73 review and pass.
