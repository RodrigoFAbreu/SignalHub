1The notification of an event that asks, with no buttons

Owner’s decision (2026-10-16): notifications carry no action buttons; every question is answered by opening the event. So a notification is what Android and Firebase build today (title and text, as 4n of the first-run page), and the server writes a first line into the text that tells the person how to answer, with the shortened message after it (decided at G8, FD1). That way a collapsed card, a heads-up card and the lock screen all say it is a question. When the question is answered, closed or deleted, the notification is removed, never replaced (1d, 1e, 1e2). Dark, 390 wide, Android 14. Tapping any of them opens the event (1h). Events without a question are unchanged. All sample names and producers are invented.

2b How the card is removed, and other limits

  • Removal is app code, not the system. The server cannot delete a notification message it already sent. It sends a data message (the kind and the event ID); the app cancels the notification with the same tag. No second channel, no heads-up, no sound, no alert replay, so the alert receiver ignores it.
  • It needs the app to run. The removal goes at normal priority, so a dozing phone gets it at its next maintenance window or when the screen turns on; a force-stopped app or a phone that is off keeps the card until then. Tapping a stale card opens the event, which says it was answered or closed.
  • A swiped-away question has nothing to remove: no card comes back.
  • An expanded card in a bundle just disappears; the bundle’s count drops.
  • The hint line is plain text. It cannot be styled or made a link. It is the first line, so the collapsed card shows it and cuts off the message after it, as drawn.
  • No buttons of any kind, as decided: no unlock prompt, no inline reply, no sending or failed states in the shade.

2c What the server must send (settled in the proposal, section 6)

  • The hint reaches only people who may answer (1c). The push text is built per recipient.
  • There is a removal in the proposal: a removal data message on answer (to everyone the question reached, the answerer’s other devices included, not the device that answered), on closesAt (scheduled, sent only if still open) and on event deletion.
  • Questions need not be data messages. They stay notification messages, shown by the system even when the app is dead; the removal is the one data message.
  • Text length. The hint adds up to about 80 characters to the push text; the 4 KiB limit is not at risk, but the message and the line together decide how tall the expanded card is.
  • Deleted event. A card for a deleted event opens “This event isn’t in your inbox any more” (App - Answering an event.dc.html, 2m). The card itself is removed with the event (1e2).
  • When the line starts. The line ships with the screens (R82b); the server release before it (R82a) sends the tag and the removal notices only, which people never see. A notification must never promise what the next screen cannot do (the reasoning of 1c).
