9The web page: where New producer lives so it never covers a producer

The problem. On the users' web page, New producer is a floating button in the bottom right of the Producers list. With a long list it sits on top of the last producer. Three ways to fix it follow, each drawn at 1440 and at 390 with 13 producers, scrolled to the end, so the last row has to be fully visible. All frames use sample data only: Rodrigo (admin) on signalhub.example, with Rui and Ana as other people.

Up to date with R72. These frames replace the Producers drawings of Web - Inbox and producers (7b, 7d) and the floating button in Web - Settings, people and states and Prototype - Web; those older pages are left as they are. What changed: the chip row has a fifth chip, Disabled, and the chips wrap onto a second line instead of scrolling sideways, so Disabled is never hidden (each chip keeps a 48 px hit area, 32 px of chip and 8 px of space above and below); disabled producers sit at the bottom of the list, yours first (pause icon, "Disabled by you · its keys do not work", which wraps instead of cutting at 390), then other people's (block icon, "Rui · Disabled"), each group A to Z.

Chosen: A (owner, 2026-10-11), a tonal New producer button in the list header, like the admin page's. B and C stay as drawn, for the record. No server change is needed for any option.

Likely cause of the bug, to confirm when building: at phone width the list area runs under the 80 px bottom bar, so the 88 px of list padding is mostly spent on the bar and the last row ends up behind the button.

Light roles are the exact ones of the design system (primary #515b92, secondaryContainer #e0e1f9, surfaceContainerLow #f5f2fa). The tonal button's text (#434659 on #e0e1f9) stays above 4.5:1.

Chosen: A, the tonal header button. It cannot cover a producer because nothing floats: there is no reserved space to size, so it holds at 1440, 1024, 600 and 390, at 200% text and in any browser zoom. It matches the admin page, whose Producers section also keeps New producer in the header as a tonal button (a header button at 390 as well), so the same action sits in the same place on both pages. It is the first stop in the pane for keyboard users instead of the last of 26. It costs one tonal button in a header that has room for it. B keeps the app's look but depends on a measured band staying right, which is exactly what failed. C is safe but hides the action at the end of a long list and on three of the five chips. The Flutter app's Producers tab keeps its floating button for now; moving it to the app bar is a separate decision.
